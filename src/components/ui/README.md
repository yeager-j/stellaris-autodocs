## What the baseline CSP governs here

The desktop CSP sets `default-src 'self'` with no `'unsafe-inline'`, no `'unsafe-eval'`, and no
`style-src-attr` (`src-tauri/tauri.conf.json`). Tauri injects nonces and hashes only for `<style>`
and `<script>` elements present in `index.html` at build time, so anything a component creates
**at runtime** gets no nonce and is blocked.

Surveyed across all 776 files of `@base-ui/react` 1.6.0 rather than assumed. CSP reaches exactly
two things in this library, and it is worth naming them separately because they are different
directives with different consequences:

**`style-src` — a real constraint, for two components.** Base UI renders exactly one `<style>`
element, `styleDisableScrollbar` in `utils/styles.js` (a scrollbar-hiding rule). It is reached only
by **ScrollArea** (`root`, `viewport`) and **Select** (`popup`, `list`).

**`script-src` — cannot fire in this application.** **Tabs** (`indicator`) and **Slider** (`thumb`)
render an inline `<script>` for SSR prehydration. It is gated on `useIsHydrating()`, whose
`getSnapshot` returns `false` and whose `getServerSnapshot` returns `true` — so it renders only
while hydrating server-rendered markup. This frontend is client-rendered and D-075 forbids SSR, so
the branch is unreachable. **If SSR ever arrives, this becomes a live `script-src` problem**, which
is the reason it is recorded rather than dismissed.

Everything else is outside CSP's reach: no `createElement('style')`, no `insertRule`, no
`adoptedStyleSheets`, and no `setAttribute('style', …)` anywhere in the package. Floating
positioning and scroll locking write through React's `style` prop, i.e. CSSOM, which CSP does not
govern — only a *parsed* `style` attribute falls under `style-src-attr`, and Base UI never produces
one. The Radix chain that would have caused this far more broadly
(`react-remove-scroll` → `react-style-singleton`) is not installed at all.

## What this means in practice

**Dialogs, dropdowns, popovers, and tooltips need nothing.** Dialog, AlertDialog, Popover, Tooltip,
Menu, ContextMenu, Menubar, NavigationMenu, Toast, Drawer, Combobox, and Autocomplete all render no
`<style>` and no inline `<script>`.

**Only `Select` and `ScrollArea` need a decision before they ship.** Phase 10 task 3 (the search
combobox) is the first ticket that needs `Select` — note that `Combobox` and `Autocomplete`
themselves are clean, so this is specifically about `Select`.

Base UI supplies the escape hatch: `<CSPProvider disableStyleElements>` or
`<CSPProvider nonce={…}>` from `@base-ui/react/csp-provider`. Three options, cheapest first:

1. `disableStyleElements`, and put the two declarations
   (`scrollbar-width: none` and `::-webkit-scrollbar { display: none }`) in `src/index.css`. No CSP
   change, no dynamic value, and we already own that stylesheet.
2. Supply a nonce. Tauri stamps `<style>` elements in `index.html` with a nonce and adds it to
   `style-src`, so a placeholder element read back through `.nonce` would plausibly work —
   **unverified**, and it makes the policy depend on a runtime value.
3. Add an explicit hash for that one rule to `style-src`.

Currently added — `button`, `input`, `label`, `alert`, `table` — is clean. Only `button` and `input`
touch Base UI, and neither reaches the style helper.

`src/architecture.test.ts` enforces the related rule that nothing under `src/` uses
`dangerouslySetInnerHTML`. It deliberately scans only `src/`; the library's own guarded use above is
out of its scope and is covered by the reasoning here instead.
