## Which components the baseline CSP permits

The desktop CSP sets `style-src 'self'` with no `'unsafe-inline'` and no `style-src-attr`
(`src-tauri/tauri.conf.json`; docs/technical-design.md, "Companion same-origin policy"). Tauri
injects nonces and hashes only for `<style>` elements present in `index.html` at build time, so a
`<style>` element a component renders **at runtime** gets no nonce and is blocked.

Verified against `@base-ui/react` 1.6.0 rather than assumed:

- Base UI renders exactly one runtime `<style>` element, from `utils/styles.js`
  (`styleDisableScrollbar`, a scrollbar-hiding rule).
- The components that reach it are **Tabs (indicator), Slider (thumb), ScrollArea, and Select
  (popup)** — those are the four modules that consume `internals/csp-context`.
- Base UI creates no style element via `createElement('style')`, `insertRule`, or
  `adoptedStyleSheets`, and never calls `setAttribute('style', …)`. Positioning goes through
  CSSOM, which CSP does not govern. The Radix chain that would have caused this more broadly
  (`react-remove-scroll` → `react-style-singleton`) is not installed at all.

So the constraint is narrow: **Tabs, Slider, ScrollArea, and Select need a decision before they
ship.** Everything currently added — `button`, `input`, `label`, `alert`, `table` — is clean;
`button` and `input` are the only ones touching Base UI, and neither reaches the style helper.

Base UI supplies the escape hatch itself: `<CSPProvider nonce={…}>` or
`<CSPProvider disableStyleElements>` from `@base-ui/react/csp-provider`. Phase 10 owns the choice —
task 3 (the search combobox) is the first ticket that needs `Select`. It should pick one of:
supply a nonce, set `disableStyleElements` and ship the scrollbar rule in our own stylesheet, or
add an explicit hash to `style-src`.

`src/architecture.test.ts` enforces the related rule that nothing under `src/` uses
`dangerouslySetInnerHTML`.
